# Paper Trail

从一篇论文出发，沿着一个问题找到一群值得放在一起读的文章。

| --- | --- | --- | --- | --- |

## 建立一个 Paper Trail

1. 复制 `TEMPLATE.md`，取一个围绕问题的文件名，例如 `hhc-continuity-of-care.md` 或 `llm-guided-routing.md`。这些只是命名示例，目前没有填入真实文献。
2. 填起点论文，写一句“为什么把这些文章放在一起”。起点是你发现这个话题的入口，不必是最早、最经典或引用最多的一篇。
3. 在群成员表中添加相关论文。每篇用群内编号 P0、P1、P2 标识；P0 是起点。PDF 仍放在话题目录，只在这里添加链接。
4. 去仓库 **Issues → New issue → Paper Trail 讨论**，填入这个 Paper Trail 页面的链接并提交。
5. 把生成的 Issue 地址填回 Paper Trail 顶部的“Paper Trail 评论区”，并在上面的索引表添加一行。

## 文章之间可以是什么关系

| 关系 | 如何说明 |
| --- | --- |
| 前置工作 | 哪个模型、假设或方法构成基础？ |
| 后续延伸 | 放宽了什么假设，增加了什么机制或约束？ |
| 方法借鉴 | 哪项技术可以迁移过来？ |
| 对照 / 不同结论 | 在相近问题上，结论或证据有什么不同？ |
| 场景迁移 | 同类问题在另一场景中如何出现？ |

这些关系可以是我们的阅读判断。作者明确引用的关系可标注“原文引用”；自己整理出的联系可标注“我们的关联”，不把相似性当作真实引用关系。

## 共同评论

整个群只用一个 Issue 作为评论区；每次评论可以先写“整体想法”或“关于 P2”，再写观点。可以讨论共同假设、相互矛盾的结论、可能的延伸，也可以直接推荐新文章。

Paper Trail 页面保留整理后的概览；持续讨论留在 Issue。之后可以把评论中的共识摘录到页面，并附上原评论链接。

同一篇论文可以出现在多个 Paper Trail 中。Paper Trail 之间也可以互相链接，无需复制 PDF。
